## 난이도 체력과 적 피해

기준 코드에는 이지/노멀/하드 체력 계수 0.9/1.4/2.1이 선언되어 있었지만, R61/R40 정규화가 지역에 생성된 체력을 덮었습니다. dist00에서 기준 main 실행을 확인했을 때 각 난이도의 보스 25,686, 일반 적 1,140이 실제 최종 체력이었습니다. 새 계산은 이 런타임 값을 난이도 1.0 기준 체력으로 보존하고, 선택 난이도에 맞춰 한 번만 배율을 적용합니다.

| 난이도 | 기준 실제 보스 / 일반 적 | 후보 보스 / 일반 적 | 체력 변화 | 적이 플레이어에게 주는 피해 |
|---|---:|---:|---:|---:|
| 이지 | 25,686 / 1,140 | 10,274.4 / 456 | 0.4배, 60% 감소 | 0.4배, 60% 감소 |
| 노멀 | 25,686 / 1,140 | 12,843 / 570 | 0.5배, 50% 감소 | 1.0배, 유지 |
| 하드 | 25,686 / 1,140 | 20,548.8 / 912 | 0.8배, 20% 감소 | 1.2배, 20% 증가 |

수치는 같은 런타임 기준 dist00 보스 및 일반 적의 예입니다. 다른 적은 해당 적의 런타임 기준 체력에 같은 난이도 배율을 적용합니다. 저장 메타데이터로 기준 체력과 적용 배율을 보존하고, 적 체력을 재정규화하는 기존 훅을 감지해 다시 배율을 적용합니다. 재적용, 난이도 전환, 저장·불러오기에서 체력이 누적되지 않으며 현재 체력 비율은 유지됩니다. 적 소유자가 확인되는 공격만 난이도 피해 계수를 적용하고 바닥·환경 위험 피해는 그대로 둡니다.

난이도 보상 1/3/7과 같은 맵의 중복 보상 방지는 유지했습니다.

## 실검무 오라

실검무 패시브를 습득한 플레이어에게만 흰색·은색 두 줄의 잔흔 오라를 그립니다. 능력치 버프는 더하지 않았습니다. 미습득, 사망, 패시브 시각 효과 끄기, 초기화 상태에서는 숨기며 저장 복원, 맵 이동, 협동 참가자별 소유 상태를 확인했습니다. 실검무의 타격 수와 대상 수 증가는 유지되고, 기존 반자동 사용 경로도 그대로입니다. 1단계 회귀 검사 결과는 타격 3회·최대 대상 2명입니다.

## 렉 및 UI 변경

프로파일에서 반복 URL 파싱, 오라 랭크 재조회, 매 프레임 같은 값의 HUD DOM 쓰기, 진단 흔적 객체와 도착 배열 생성, 반복 `matchMedia` 호출을 확인했습니다. URL 경로와 coarse-pointer 쿼리를 캐시하고, HUD 값이 달라질 때만 DOM을 갱신하며, 오라·진단 계산과 자산 경로 정규화의 중복 작업을 줄였습니다. 손전등 시야 안의 효과·투사체만 그리는 기존 시야 경계도 활용합니다. 효과를 삭제하거나 해상도를 강제하지 않았습니다. PC/모바일 손전등 기본값은 기존 동작을 보존하고 사용자 선택·저장값을 우선합니다.

안내·토스트·오류 알림은 플레이 화면과 조작부 사이의 38px 알림 공간으로 옮겼습니다. 중요한 오류는 짧은 알림으로 남기고 설정의 상태/진단에서 상세 내용을 볼 수 있습니다. 터치 안전 영역과 가로·세로 조작부 위치를 검사했습니다.

## 성능 측정

Chromium 151 headless, SwiftShader 소프트웨어 렌더러에서 같은 dist00 전투 장면(플레이어 (15,19), 적 6마리, 전투 활성, 게임 캔버스 1365×672)을 2.5초 예열 후 약 8초 프로파일링했습니다. 아래는 실제 기기/GPU 측정이 아닌 에뮬레이션입니다.

| 지표 | 기준 main | 후보, 손전등 시야 켬 |
|---|---:|---:|
| 샘플 프레임 수 | 39 | 37 |
| 평균 프레임 시간 | 214.95 ms | 227.02 ms |
| p50 / p95 / p99 | 200 / 266.7 / 450 ms | 216.6 / 250.1 / 483.3 ms |
| 샘플 종료 JS heap | 121.0 MB | 60.4 MB |
| 샘플 중 JS task 시간 | 8,599 ms | 8,744 ms |
| layout / style 재계산 | 41 / 40 | 39 / 38 |

후보 평균 프레임 시간은 기준보다 12.07ms(5.6%) 높았고, p95는 낮아졌지만 p50·p99는 높아졌습니다. JS heap 표본은 기준 60.0→61.3MB, 후보 54.1→50.6MB로 서로 다른 시작점과 GC 시점을 포함합니다. 이 값은 메모리 개선을 입증하지 않습니다. 표본 변동과 화면 상태를 고려하면 구조 변경으로 프레임 이득을 입증하지 못했습니다. 주요 잔여 CPU 표본은 Three.js `getParameters/getProgram`, phase1 탐색 경계·렌더, 시야 광선 판정, textured floor 경로였습니다.

390×844 CSS 화면·DPR 2 iPhone 사용자 에이전트 에뮬레이션의 후보 전용 비교에서는 손전등 시야 켬이 평균 96.66ms (p50 83.4, p95 116.7, p99 383.4ms), 전체 시야가 91.28ms (p50 83.4, p95 100.1, p99 116.7ms)였습니다. 이 값도 기기 전후 개선이 아니라 에뮬레이터에서 시야 설정을 바꾼 후보 내부 비교입니다.

- 브라우저 회귀: 데스크톱 및 Windows 터치 PC, 모바일 세로/가로, 설정 열기, 실제 터치 입력, 알림·진단 비겹침, 저장 2회 복원, 맵 이동, 패시브 표시를 검사했습니다. 결과 파일과 5개 화면 캡처는 동일 후보 코드 커밋 `dd1a2de5dc768128b3517140fd11eefdbcbc1ba5`에서 생성합니다.
