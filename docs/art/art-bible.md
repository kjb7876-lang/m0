## 적용 상태와 읽는 순서

이 문서는 현재 자산을 평가하고 새 파생본을 만드는 프로젝트 기준이다. 기존 `storyworld-art-style`의 손으로 칠한 고딕 판타지, 두 색 영웅 효과, 원본 보존 규칙을 따른다. 아래 수치 중 **제안**으로 표시한 것은 제작·검수 목표이며 현재 제품이 그 수치를 충족한다는 뜻이 아니다. 감사 점수와 실제 증거는 [전수조사](art-audit-20261105.md)를 함께 읽는다. 외부 미술감독 문서의 원문은 사용하지 않았다.

## 화풍과 형태

질감은 칠한 돌·낡은 금속·가죽·유기체로 통일한다. 큰 덩어리의 실루엣을 먼저 읽고 표면의 작은 상처를 나중에 읽게 한다. 영웅은 길게 뻗는 신체와 무기, 몹은 역할을 가르는 비대칭 덩어리, 보스는 최소 두 배 몸키와 공간을 점유하는 실루엣으로 구별한다. 귀여운 치비, 둥근 만화 구름, 선명한 픽셀 가장자리, 그림 속 문자와 현대적 앱 아이콘은 새 자산에서 제외한다. 현재 남아 있는 다른 결의 자산은 검수 목록에 남기며 원본을 덮어쓰지 않는다.

## 명도 띠·경계·모바일

제안 목표는 CIE L* 기준 비보행 배경 8–18, 벽 옆면 18–28, 보행 바닥 30–45, 벽 윗면·문틀 45–58, 영웅 주요 윤곽 60–78이다. 피격·정화의 작은 절정만 80 이상을 허용한다. 이것은 전역 밝기 필터 값이 아니다. 캡처에 수동 ROI를 정해 바닥/벽/문을 따로 측정하고, 어두운 방은 바닥–벽 ΔL* 10 이상을 출발점으로 검토한다. 최종 판정은 흑백에서도 벽·길·문을 찾을 수 있는지로 한다.

벽과 바닥 접점의 좁은 접촉 그림자, 벽 윗면의 절제된 밝은 띠를 우선한다. 바닥 잡음은 캐릭터 윤곽보다 약하게 한다. 이동 가능한 경계는 장식의 세부보다 선명하게 만든다. 영웅 근처에는 안개·그레인이 윤곽을 덮지 않게 한다. 전역 검은 안개를 없애거나 확정 맵·충돌 경계를 바꾸지 않는다.

모바일은 CSS 390×844·DPR3에서 먼저 보고 가로 화면도 후속 확인한다. 캡처의 물리 픽셀 수가 3배여도 내부 WebGL 해상도가 3배라는 뜻은 아니다. 화면 한쪽 손가락이 가리는 동안 영웅·적·장판·출구가 구분돼야 한다. UI 본문 14 CSS px, 중요 조작 44 CSS px 터치 영역을 제안 목표로 삼고 실제 기존 설정을 별도 확인한다. 실제 해상도·lowFx·LOD·대비 구현 및 성능 예산은 CX-0023 담당 범위다.

## 조명과 그림자

현재 렌더러는 DirectionalLight `#ffe4bd`, 세기 1.7, 위치 `(10,16,9)`, AmbientLight 흰색 0.9를 사용하며 그림자맵은 꺼져 있다. 벽에는 구워진 빛이 있고 일부 재질은 MeshBasicMaterial이라 한 조명을 켠다고 모든 그림이 일치하지 않는다. 코드의 위치를 화면 좌상단 광원이라고 단정하지 않는다.

새 파생 자산은 **화면 좌상단의 따뜻한 주광 + 차가운 저채도 음영**을 기본 제작 제안으로 고정한다. 바닥과 만나는 발 아래에 눌린 접촉 그림자를 두고, 큰 광원 반대편의 그림자 방향을 비교한다. 실제 장면의 벽·캐릭터·조형물 그림이 다른 방향이면 각각 기록한다. 불·성광은 국부 보조광으로 처리한다. 창백한 영웅을 안개처럼 반투명하게 만드는 것으로 크기·명도 문제를 숨기지 않는다.

## 몸키·프레임·피벗

**180px는 시트 안의 영웅 몸키 기준**이며 PC 화면에서 180px로 그리라는 뜻이 아니다. 현재 엔진의 actorHeight는 66×zoom 계열이다. 화면 축소 배율과 authored body height를 따로 기록한다.

| 대상 | 영웅=180 기준 제안 | 비율 |
|---|---:|---:|
| 일반 인간형 몹 | 144–234px | 0.8–1.3 |
| 작은 몹 | 90–144px | 0.5–0.8 |
| 대형 몹 | 234–324px | 1.3–1.8 |
| 보스 | 최소360px | 최소2.0 |
| 낮은 상자·단서 조형물 | 45–108px | 0.25–0.6 |
| 의자·제단 | 108–180px | 0.6–1.0 |
| 문 열림 높이 | 252–324px | 1.4–1.8 |
| 기둥·대형 나무 | 360–720px | 2.0–4.0 |

보스 최소 2배는 기존 요청과 일치한다. 다른 비율은 제작 제안이며 밸런스·판정 크기를 바꾸지 않는다. 실제 보스 경로의 최종 렌더 크기를 확인한 뒤 판단한다.

다음은 기존 스킬의 제작 제안 규격이며 현재 RC5 아틀라스의 실제 칸 규격과 다를 수 있다. 현재 경로별 sourceRect/pivot/visibleHeight는 capture manifest를 별도로 확인한다. 영웅 칸 192×256, 발 피벗 `(96,226~227)`, 몸키 약180을 기준으로 원본과 나란히 놓는다. 프레임마다 발 위치·몸키·알파 경계를 기록한다. 걷기는 실제 이동 입력 중 찍고, 피격·공격은 상태명만 보지 말고 최종 그림 경로와 픽셀 변화를 확인한다. 방향별 대기/걷기/공격/피격의 연속 프레임과 피벗 안정성은 단일 정지 사진으로 검증할 수 없다.

## 이펙트·UI

프레임 시트·칠한 스트립을 우선한다. 기본 도형의 원·선·부채꼴을 최종 영웅 스킬 그림으로 새로 쓰지 않는다. 범위 예고는 플레이 판독에 필요하므로 유지하되 칠한 어두운 핏빛/금빛 텍스처로 표현한다. 효과의 시작·절정·소멸을 분리하고 영웅·적·장판의 윤곽을 동시에 읽을 수 있게 한다. 동시 개수 상한과 저사양 감쇠를 보존한다. CX-0025가 스킬별 도형 제거·시트 교체를 담당한다.

기존 R106 스프라이트·R163 추출 시트·R178/R190/R292 스트립을 먼저 검토한다. R163은 지정 추출기로 만들고 사람·문자 포함 시트를 제외한다. `hit-flash` 치비 시트는 쓰지 않는다. 새 그림이 필요하면 8–16프레임, 256×256 권장, RGBA, 영웅 두 색, 발광 번짐과 소멸, 사람·문자 없음, index.json의 출처/규격/해시를 요청한다.

UI는 짙은 금속·낡은 금테, 쪽지는 바랜 양피지, 진료기록은 오래된 병원 서식, 기억 조각은 어두운 깨진 유리로 구별한다. 새 사용자 문구는 한국어로 쓴다. 현재 HAPIL/STORY/EGO/HP 등의 기존 라벨은 관찰된 불일치로 기록하며 이번 감사에서 고치지 않는다. 쪽지 본문은 효과광·배경 질감보다 우선 읽혀야 한다.

## 검증 절차와 표

1. 기준/후보 SHA와 manifest SHA를 고정하고 실제 빌드한다. 동일 viewport/DPR/seed/위치/영웅/지역/상태를 사용한다.
2. PC1920×1080과 모바일390×844 DPR3에서 일반·흑백 쌍, 실제 렌더러, 자산 누락·콘솔 오류, 최종 사용 그림을 기록한다.
3. 자연 플레이, 위치 배치 fixture, 상태 고정 fixture, 헤드리스/SwiftShader, 물리 GPU, 모바일 실기기를 구분한다. 어떤 증거가 없는지 함께 쓴다.
4. 만든 사람과 다른 심사자가 실제 이미지 파일의 픽셀을 열고 파일명·해시·관찰·다섯 점수를 남긴다. 축소 연락시트만 본 경우 그 한계를 적는다.
5. `(화풍×3 + 형태×2 + 가독성×2 + 적용성×2 + 재현성)/10`으로 합산한다. 각 점수는 0–10이다. 점수8.5 이상이고 요구 증거가 모두 충족돼야 **검증됨**, 증거가 있는 불완전 평가는 **임시**, 보지 못했으면 점수 없이 **미검증**으로 둔다.
6. 전후 비교·성능·피벗·동작 연속성은 각 해당 수정의 후속 검증이다. 이번 감사 기준 캡처를 개선 후 화면이라고 부르지 않는다.
