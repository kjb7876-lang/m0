# R493 렉 개선 — 같은 셰이더를 버렸다 다시 컴파일하지 않기 (2026-11-09 밤)

## 재현·증거 (헤드리스 640×360, 777 → 길잡이 켬, 지역 입장 3초 뒤부터 30초)
- `gl.linkProgram`(셰이더 컴파일·링크) 횟수 vs 그 순간 살아 있는 프로그램 수:
  dist00 47번 / 26개, ep1a08 92번 / 37개, ep1b04 159번 / 56개 → 같은 프로그램을 버리고 다시 만든다.
- 원인 ①: three 는 프로그램을 쓰는 재질이 모두 버려지면(장면 명령 줄이 사라질 때) 프로그램을 지우고, 같은 재질이 다시 나오면 새로 컴파일한다(대부분 'basic' 그림 재질).
- 원인 ②: 장면 명령의 그라디언트 칠(CommandScene.gradientMaterial)은 직접 짠 셰이더라, 재질이 다 사라질 때마다 셰이더 글 번호가 버려져 다음엔 새 번호 → 새 열쇠 → 새 컴파일(ep1b04 25초에 25번).
- 컴파일·링크는 GPU 드라이버 일이라 실기기(특히 Windows ANGLE·휴대폰)에서 한 번에 수~수십 ms 멈춘다. 이펙트·몹이 나타나는 순간의 '멈칫' 유력 원인.

## 고침 (perf-r493.js, 새 오버레이)
- `renderer.info.programs`(three WebGLPrograms 의 programs 배열)에 새 프로그램이 들어올 때 usedTimes 를 1 올려 붙잡는다(상한 256).
- 그라디언트 셰이더와 같은 글의 지킴이 재질을 한 번 컴파일해 두어 셰이더 글 번호를 고정한다. 지킴이가 지키는 번호가 아닌 직접 짠 셰이더 열쇠는 붙잡지 않는다(상한 낭비 방지).
- 그림·순서·판정·저장은 그대로. 끄기 `storyworld.r493.perf {"pinPrograms":false}`.
