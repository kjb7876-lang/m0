# R441 렉 개선 — 측정·심사 기록

## 측정 방법
헤드리스 Chromium(SwiftShader, GPU 없음) 480×270·1280×720, 777 → 길잡이 켬, 지역마다 12초 데운 뒤 15초 CPU 표본(0.5ms).
GPU 비용은 SwiftShader 라 잴 수 없다(실기기 그래픽 비용 = 미검증). Playwright 아래에서는 `new Error()` 한 번이 ~9–20µs 로
실제 크롬보다 크게 잡히므로 R302(스택 잡기) 비중은 부풀려진 값으로 보고, 판단은 실기기에서도 그대로 드는 비용(캔버스 굽기·충돌 JS) 위주로 했다.

## 고친 것과 실측
1. **R409 테두리 굽기** — 열쇠가 Image 물체 번호라 지역을 옮길 때마다(본편이 그림을 새 Image 로 다시 받음) 같은 영웅 걷기 칸도 다시 구웠다.
   주소가 있는 그림은 주소로 기억, 캐시는 288장·픽셀 합계 7M(예전 96장이 실제로 쓰던 ~6.7M 와 같은 메모리).
   ep1b03→dist02 왕복 5번(각 20초): 새 굽기 **246 → 117번**, 세 번째 재방문 **50 → 1번**.
   그리고 한 장면에 굽기가 6ms 를 넘으면 나머지는 다음 장면으로(장면마다 1장은 굽는다) — 지역 입장·무리 등장 때 한 장면 끊김을 나눈다.
2. **충돌 검사(blocked) 장면 안 기억 — perf-r441.js(새)** — tick 한 번 안에서 같은 (x,y,반지름,방) 질문이 29–31%, 답이 달랐던 적 0번.
   글자 열쇠 Map 은 질문(~1.5µs)보다 비싸서 오히려 느렸다(실측 후 버림) → 숫자 해시 표. 켬/끔 1.5초씩 번갈아 30초:
   질문당 시간 dist00 1.74→1.49µs(−15%), ep1a08 2.88→2.08µs(−28%), ep1a10 2.91→2.28µs(−22%). 문 세대·방이 바뀌면 그 즉시, 나머지는 다음 tick 에 반영.
3. **R302 영웅 색 호출자 찾기** — play-r111 보스·자아 그림(12초 1,900번)마다 '은색실이 더 깊을 수도' 하고 전체 스택을 한 번 더 잡던 것 없앰
   (threadSlash 는 3·4칸째에서만 그림을 부른다 — 검사가 구조를 확인). 소유 정보가 있으면 스택을 아예 안 잡음. 판정 동일(78가지 호출 조합 비교, 차이 0).
