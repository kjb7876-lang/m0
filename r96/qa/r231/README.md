# R231 — 길잡이가 얇은 벽 주머니에 갇히지 않게 + 닿음 계산이 얇은 벽을 넘지 않게

- 재현: 스토리 실플레이(헤드리스, 길잡이·미카엘라)에서 dist01 거미동굴 (12.5, 21.6)에 50분 넘게 서 있었다. 길 0, 목표 없음, 남은 적 7.
  - 같은 자리에 세우면 매번 재현된다(헤드리스).
- 원인:
  1. 그 자리는 칸 경계에 놓인 얇은 벽(두께 .24)으로 사방이 막힌 주머니라, 걸어서는 들어갈 수도 나올 수도 없다.
  2. R222 의 6초 순간이동(hop)은 길 앞쪽 2칸 안의 길점으로 옮기면서 끝점만 봤다. 그래서 얇은 벽을 넘어 주머니로 들어갈 수 있었다(가장 그럴듯한 경로).
  3. 엔진 길찾기는 거기서 길을 0 으로 돌려줘 아무것도 못 했다.
  4. 처음 의심한 '닫힌 보스문 우회'는 칸 중심만 보는 검사가 얇은 문·벽을 건너뛴 착오였다. 실제로 걸으면 문에서 막힌다. 같은 착오가 R225 닿음 계산에도 있었다.
- 고친 것(그림·판정·피해 그대로, 길잡이·닿음 계산만):
  - `guide-unstick-r222.js`:
    - hop 은 직선 위 모든 지점이 막히지 않을 때만 한다.
    - 길이 아예 없을 때는 걸을 수 있는 칸 길(칸 경계 중간점도 검사)로 가장 가까운 적 쪽 3칸 앞에 선다.
    - 걸어서 나갈 길이 없으면(이미 갇힘), 입구에서 걸어서 닿는 칸 중 가장 가까운 곳(8칸 안)으로 꺼낸다. 닫힌 문 둘레 1.2칸은 넘지 않는다(stats.unsealed).
  - `reach-r225.js`: 닿음 너비 탐색이 칸 경계 중간점도 본다. 문 둘레는 이전처럼 열린 것으로 본다.
- 검사: `node r96/qa/r231/r231-cpu-check.cjs` 6/6 (가상 지도: 틈 있는 얇은 벽 + 막힌 주머니).
  - r222(22/22)·r225(13/13)·r176·r230 검사도 다시 돌려 통과.
- 헤드리스 dist01 재현: 주머니에서 꺼내는 일 1번 → 그 뒤 정상 길찾기로 남은 적 33 → 1.
- 미검증: 다른 지역의 같은 주머니 수(전수 검사 미실행), GPU·실기기, 자연 플레이.
