# R522 병원 얇은 벽 붙이기 — 기록과 7분야 심사

대상: `r96/client-source/hospital-walls-r522.js`(새 오버레이). 증거: `r522-walls-1.jpg`(남쪽 병실 C 전·후), `r522-walls-2.jpg`(가운데 복도 후), CPU 검사 31항목.
**헤드리스(소프트웨어 렌더) 확인이다. GPU·실기기·자연 플레이는 미검증.** 심사는 작업한 세션이 스스로 매긴 것이다(독립 심사 아님).

## 무엇을 왜
- 사용자 2026-11-10 "얇은벽은 항상 굵은 벽과 붙어있도록". 병원 본관 미로의 얇은 가림벽 20개 가운데 18개는 한쪽 끝이 굵은 벽에 붙어 있고, 2개만 양 끝이 다 떠 있었다.
- 길이·방향은 그대로 두고 자리만 옮겼다: 남쪽 병실 C 가림벽 x48~57 → x53~62(y97), 가운데 복도 가림벽 x31 → x33(y68~74).
- **이 두 벽은 충돌·길찾기·시야도 함께 옮겨진다.** 병실 C 의 왼쪽 통로는 4칸 → 9칸으로 넓어지고 오른쪽 통로(5칸)는 닫힌다. 방 위아래는 왼쪽 통로로 이어진다.
- 병원 본관에만 적용된다. 같은 미로 틀을 쓰는 다른 지역과 엔진 직접 호출은 원래 끝점을 읽는다(브라우저에서 dist01 확인, `qa/layout-validation.cjs` 그대로 통과).

## 확인한 것
- 브라우저: 병원 벽 끝점 두 곳이 옮긴 값, 옛 자리 `blocked` 거짓·새 자리 참, 표는 쉬는 동안 원래 값, R521 가구 117점·빠진 것 0.
- CPU: 길 연결(시작 3곳에서 닿는 마디 56곳·출구 문)이 전후 같음, 걸을 수 있는 넓이 변화 1% 미만, 문·보스방과 떨어져 있음.
- 엔진 검사 `layout-validation`·`r95/map-current-check`·`r81/geometry-contracts` 통과.

## 점수 (R522, 자체 심사)
미술 7.9 · 연출 7.8 · 구도 7.9(병실 C 가운데가 벽에 덜 가림) · 공간 8.2(벽이 구조물처럼 읽힘) · 조명 7.8 · 애니 7.7(변화 없음) · UX 7.8(통로 하나가 닫혀 돌아가는 길이 생김) = **평균 7.87 → 통과**.

## 검사 기대값을 바꾼 곳
- `r521-cpu-check.cjs`·`r176-cpu-check.cjs`: 스크립트 태그 순서 정규식에 R522 태그 자리를 넣음.
- `r522-cpu-check.cjs`(새 검사)에서 구현 뒤 고친 기대값 2곳: "마디 60곳 모두 닿음" → "56곳(나머지 4곳은 실측 지도에서 닫힌 보스실 문 뒤, 전후 같음)", "목표에 닿음" → "전후 같음"(목표도 보스실 안). 코드가 아니라 검사 쪽 가정이 틀렸던 것이다.

## 미검증
- 실제 플레이에서 몹이 옮긴 벽 둘레로 길을 찾는 모습, 길잡이 화살표가 병실 C 에서 도는 모습.
- 길잡이 마디 south-ward-c(53,97)는 원래도 이 벽 위에 있었고 지금은 벽 끝에 있다(전과 같은 조건이지만 실제 동선은 눈으로 보지 않음).
- 이미 진행 중인 저장을 이어 할 때(지도는 들어갈 때 새로 지으므로 반영될 것으로 보지만 확인 안 함).
