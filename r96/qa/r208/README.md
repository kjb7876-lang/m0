## 2. 횃불 원형 시야 (light-r182.js R208-light-3)
원인: R24 둘레 시야 반지름이 화면 크기(8~18칸)라 원이 보이지 않았고, R100 이 시야 밖을 32~58% 밝기로만 낮춰 흐릿했음.
수정: 횃불 모드에서 화면 위에 86% 어둠을 깔고 영웅 둘레 5.2칸 원(벽에 막히면 그 자리 +0.75칸)만 뚫는다. 가장자리 28% 부드럽게, 따뜻한 빛 10%, 살짝 일렁임.
사몽 미로·어두운 구역은 기존 samong-r103 빛을 그대로 쓴다.

## 3. 지역 전환 (cave-r204.js)
- 동굴 지형 빌드가 끝나기 전 약 3초 동안 원래 네모 지형이 보이던 것: 빌드 대기 중 원래 지형을 가리고(veil), 지형장을 전환 직후 미리 계산, 텍스처를 2.5초 뒤 미리 읽음.
- 흔들림: 헤드리스 측정에서 카메라 진동은 없었고(전환 때 1회 순간이동), 로딩 중 6초에 12프레임만 그려짐. 전환 중과 들어간 뒤 2.5초 동안 화면 흔들림(shake)을 0 으로 둔다.
  실기기에서 사용자가 본 흔들림과 같은 현상인지는 **미검증**.

## 4. 동굴 바위 판정 범위(cave-r204.js)
전수 검사 projectile 의 "dist01 baffle 시작점" 검사가 CPU 부하에 따라 통과·실패가 갈렸다: 렌더가 검사보다 먼저 돌면 R204 거리장이 생겨 시작점(바위 언덕 안)이 막힘.
투사체는 원래 terrainContact153 으로 벽을 판정하므로, R204 바위 언덕 판정을 몸 크기(반지름 > .2: 영웅·몹·길잡이 .29) 질의에만 적용해 결정적으로 만들었다.
단독 실행 13/13 확인 후 수정, 4묶음(projectile·environment·campaign-map-admission·map-perimeter) 재실행.

PR #132 첫 CI 에서 전수 검사 enemy-facing("모든 탐침에서 몸 프레임이 그려진다")이 dist01 거미줄에 묶인 수호병에서 실패.
