## 2. 찾은 문제와 고침
- 6·7단계는 창 크기와 상관없이 배율 1.75·2 를 곱했다. 큰 창(2560×1440 이상)이면 게임 캔버스와 전투 HUD 캔버스가 각각 4K 를 훨씬 넘는 크기가 되어, 화면에는 어차피 2560 폭으로 줄여 보이는데 그리기·메모리만 2~4배 든다(최고 사양에서 렉·메모리 위험).
- 고침(`perf7-r1043.js`, R1052 `fit`): 6·7단계 배율은 캔버스가 4K(3840×2160 = 829만 화소)를 넘지 않게 줄인다. 단 5단계(엔진 기본 배율)보다 낮아지지는 않는다. 창 크기가 바뀔 때마다 다시 계산한다.
  - 1280×720·1920×1080 창: 그대로 1.75·2(바뀜 없음). 휴대폰: 그대로.
  - 2560×1440 창: 1.52(3891×2122). 3440×1440 창: 예산에 맞춰 줄임.
- 판정·피해·저장·세 모드 공통 코드는 그대로. 1~5단계는 그대로.

## 3. 단계별 실제 차이(2560×1440 PC, 고친 뒤)
| 단계 | 배율 | 게임 캔버스 | 3D 캔버스 | lowFx | 빛·날씨·조명·맞춤 |

- 배율 1 모니터 PC 에서는 2·3단계, 4·5단계 사이 차이가 작다(배율이 같고 효과·그림 절반 여부만 다름). 기기 배율 1.25 이상(노트북·휴대폰)에서 단계 차이가 커진다.
- 큰 창에서 6·7단계 배율은 같아지고, 7단계는 빛·날씨를 강제로 켜는 것만 다르다.
- 프레임 비용: 헤드리스 소프트웨어 렌더링의 draw() 시간은 같은 단계에서도 22~139ms 로 흔들려 단계 비교에 못 쓴다. 화소 수(=GPU 채우기 비용 비례)로 보면 2560×1440 7단계가 1,430만 → 824만 화소(42% 감소).
