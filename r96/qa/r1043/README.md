## 1. 전수조사 방법
- `r1043-inventory.mjs`(헤드리스)로 게임 중 설정 창의 모든 조작을 뽑았다: PC 204개, 휴대폰 221개(휴대폰 전용 6개: 시작 메뉴로·진행 저장·화면 단추·기술 자동 발동 등).
- 정리는 **표시만** 바꾼다: 숨긴 칸의 기능·기본값·저장값은 그대로다(되돌리기 쉽고, 기존 검사·세이브를 건드리지 않는다).

## 3. 성능 7단계 (간이설정 맨 위 '성능 단계')

| 단계 | 내용 | 화면 배율 |
|---|---|---|
| 1 초저 | R1023 낮음 + R150 가벼운 화면 + 빛·안개·날씨·국지 조명·빛 맞춤 끔 | 0.75 |
| 2 낮음 | 지금 최저(휴대폰 공개본) | 1 |
| 3 보통 | 200만 화소 이상 그림만 절반 | 1 |
| 4 높음 | 가벼운 효과 끔 | ≤1.25 |
| 5 PC급 | 지금 PC 기본 | ≤1.5 |
| 6 고화질 | PC급 + 촘촘히 그려 줄임, 가벼운 화면 자동 끔 | 1.75 |
| 7 풀옵션 | PC급 + 빛·날씨 모두 켬 | 2 |

- 휴대폰 기본은 '자동'(R1023 자동: 2단계로 시작해 넉넉하면 5단계까지). 지금 수준이 최저 기본이다(#572 꺼짐 위험). 휴대폰 6·7단계 배율은 기기 배율을 넘지 않는다.
- PC 기본(한 번도 안 고름)은 아무것도 바꾸지 않는다.

## 4. 렉
- 프로파일(`r1043-profile.mjs`, 헤드리스 무한 생존): JS 약 30ms/장면, 대부분은 소프트웨어 그리기(GPU 없음).
- 찾은 끊김: `reach-r225` 가 살아 있는 적이 3마리 이하일 때 3초마다 지역 전체(약 1만 칸)를 두 번 훑으며 `blocked()` 를 2만 번 불렀다 → 한 번 56~67ms(3초마다 끊김).
  고침: 같은 레이아웃·지역이면 15초 동안 벽 판정과 BFS 결과를 다시 쓴다. 다시 잰 값 0ms(`r1043-reach-cost.mjs`). 15초마다 한 번은 여전히 약 60ms(5배 드묾).
- 프레임 측정(`r1043-frametime.mjs`)은 헤드리스 소프트웨어 렌더링 값이라 실기기와 다르다(변동 큼).
