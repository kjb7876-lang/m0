# R1111 기억사수 위·아래 조준 — 쏘는 사이 옛 그림이 나오던 경로

사용자 제보(11-16 10:45Z): "위·아래 공격이 예전 그림으로 나온다". 공개판 aa33dca 빌드를 헤드리스로 실제 연사 간격(쿨다운 그대로)으로 돌려 칸을 셌다.

## 원인(실측)
| 장면 | 옛 그림이 그려진 경우 |
|---|---|
| 위 조준 연사 | 휘두르기(약 0.2초)가 끝나면 다음 발까지 서 있기에 R128 idle-n(소총 멘 뒷모습)이 약 0.25초씩 반복 — 51프레임 중 30프레임. 휘두르기 꼬리에서 R143 attack-n 도 1~3프레임 |
| 아래 조준 연사 | 적이 잠깐 안 잡히는 프레임(맞고 밀림·막 죽음)마다 서 있기가 조준을 잃고 idle-n(뒷모습) — 50프레임 중 26프레임 |
| 위쪽 걷기 사격 | R128 walk-n 옛 그림(새 Dots 걷기 시트 없음 — 보류, CX-0121GN GN-2 는 Dots HOLD) |

휘두르기 자체(attack-n3·attack-s2)는 새 Dots 그림이 맞았다. 멈춰 서서 쏠 때 사용자가 본 "예전 그림"은 쏘는 사이 서 있기와 꼬리 프레임.

## 고침
1. 서 있기: 적이 잠깐 안 잡혀도 마지막 조준(2.5초)을 써서 정 아래면 Dots idle-s2, 대각이면 기존 대기 6칸으로 유지(aimHold).
2. 위(정북): R128 idle-n 대신 Dots CX-0121GN GN-1 위쪽 서 있기 6칸(attack-n3 자세 재사용·숨쉬기만, 120ms). `{"idleN6":false}` 면 attack-n3 겨눔 칸 순환, `{"northIdle":false}` 면 옛 그림.
3. 휘두르기 꼬리(attackAnim 0)에도 R143 attack 칸이 있으면 바꿈.

## 검사
- 실패 테스트 먼저: `r1111-browser.mjs` 가 main 빌드에서 위 30/51, 아래 26/50 으로 실패 → 수정 뒤 0/42, 0/39 통과.
- CPU r1111 13, r991 79, r1003 53, r1045 54, b 19, c 33, d 24, r1101 17, r1101b 33, r1101c 15 통과. r1101b-browser 도 통과(se6 45·ne6 5·e6 118 프레임).
- 기존 검사 1줄 수정(비 CI r1101-browser): "쏜 뒤 서 있기" 기대를 attack-e4 에서 R1101b 이후의 idle-e6 도 받게.
- 캡처 눈 확인: 위 조준 4장 모두 소총을 어깨 너머로 겨눈 뒷모습, 아래 조준은 앞모습 겨눔. (하네스에 다른 적이 끼면 조준이 정당하게 바뀌어 뒷모습 한 장이 섞임)
- 헤드리스 결과라 그래픽 검증 아님. GPU·실기기 미검증.
