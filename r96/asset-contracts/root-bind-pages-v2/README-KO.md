# r6 뿌리 속박 전후 분리 후보

원본 R90의 24프레임을 새 그림 없이 분리했다. 원본 source/ 및 R90/r5는 변경하지 않았다. 상부는 뒤, 낮은 발목/정강이 띠는 앞으로 배치하는 화면 공간 가독성 파생안이다. 실제 뿌리의 숨은 뒷면을 복원한 해부학적 분할은 아니다. 모든 프레임의 actor 없는 재합성은 원본 보이는 픽셀과 정확히 같으며, 두 레이어의 알파 중복 픽셀은 0이다. 투명 픽셀 RGB까지 보존하는 원시 배열 합도 정확하다.

원본 source canvas 512×512, 발 pivot (256,440), 출현8×80ms/감기4×80ms/유지4×120ms/해제8×80ms를 유지한다. 정상 source-over straight RGBA8; additive 금지. front/back를 서로 다른 배율·좌표·시계로 재생하지 않는다. 기존 단일 overlay와 새 두 레이어를 동시에 그리지 않는다.

review의 4개 시트에서 24프레임 전부 정지 이미지로 검토했다. 파란 actor는 합성 도형이며 실제 게임/캐릭터 스크린샷이 아니다. 얼굴·몸통을 가리지 않는 차이를 보여 주는 가독성 예시일 뿐, 실제 무기·카메라·충돌 검증은 없다. 현재 상부 cage 자체의 모양은 보존되므로 실제 0.48배 이동 상태에 부착시켜야 하며, 완전 행동불가/바닥 고정으로 해석하지 않는다.

유지 루프 15→12의 premultiplied RGBA 평균 차이 0.05707은 인접 최대 14→15의 0.06688보다 크지 않다. 특별히 마지막→첫 프레임만 나쁜 근거가 없어 새 유지 그림/키를 만들지 않았다. 원본 유지4키와 480ms를 보존한다. 차이 수치는 지각적 부드러움 증명이 아니며 seamlessVerified=false이다.

## 제안 상태 계약
- 실제 native 상태를 유일한 판정 근거로 사용한다. 효과 출현을 기다리지 않고 상태 적용 즉시 기존 0.48 이동배율이 작동해야 한다. 이 팩은 native 상태를 수정하지 않는다.
- actor+status당 하나의 논리 핸들(뒤/앞 2렌더러)만 둔다. 재적용은 native until을 갱신하고 중복 핸들/추가 피해를 만들지 않는다.
- 960ms 이전 조기 해제는 현재 출현 프레임을 160ms 이내 희미하게 제거한다. 갑자기 완성 cage 해제16번으로 점프하지 않는다.
- 감기 완료 뒤 정상 상태 해제는 원본16~23번640ms를 재생하며 마지막80ms에 알파0으로 끝낸다. 상태 효과는 이미 해제되어 이동을 제한하지 않는다.
- release 도중 재적용은 같은 핸들의 release를 취소하고 새 출현으로 재시작한다. 순간 시각전환은 실제 재생 검토가 필요하다.
- 사망/탈스폰/맵 이동은 장식 release를 남기지 않고 두 렌더러와 타이머를 즉시 정리한다. save에는 장식 핸들을 저장하지 않는다. 복원은 native 남은 시간에서 단일 핸들을 재구성한다.
- 시계는 게임의 pause-aware elapsed time을 받아야 한다. 프레임 수/벽시계 독립 진행을 섞지 않는다.

simulate_contract.py는 위 일부 조건의 별도 CPU 모델이다. 지연 tick을 포함한 6가지 시나리오 통과는 실제 게임 코드나 저장·일시정지 구현 검증이 아니다. 게임 연결/브라우저/GPU/모바일/실플레이/성능은 미검증이다.

## 메모리와 파일 사용
전체512셀 두 atlas는 검토/교환용이며 합계48MiB다. 런타임에 이를 단순히 올리면 원본24MiB보다 나빠진다. compact atlas 3페이지(앞1/뒤2)은 고정 레이어 bbox+2px투명패딩을 사용하여 합계20.384765625MiB(RGBA8, mipmap/driver복제 제외)다. 원본보다 약15.06% 작은 산술적 footprint이며 실제 GPU 메모리 측정은 아니다. manifest의 pageIndex/rect/sourceOffset/localPivot을 적용해 원본512canvas 위치로 복원한다. 프레임별 맞춤 리사이즈 금지. 원본/전체atlas/compact를 동시에 적재하지 않는다. 64MiB pool/8atlas/16instance 예산을 늘리지 않는다. 2렌더러의 draw call 비용은 측정하지 않았다. 투명패딩은 extrusion이 아니므로 bilinear 경계/반투명 분할선·축소·mipmap은 실제 엔진 검토가 필요하다.

독립 검사 전 후보이며 배포/게임 적용 없음. 재현 순서: build.py → compact.py → simulate_contract.py. 새 페인팅 없음.

## v2 페이지 재배치
앞1792×930, 뒤1792×1710 및1792×342로 모든 페이지를2048 이하로 재배치했다. 이미지/타이밍/알파/분할은 변경하지 않았다. 총 nominal RGBA8는20.384765625MiB로 동일하다. 기존8atlas 슬롯 중3개를 소비하므로 사용량을 함께 고려해야 한다. 이전2052높이 후보는 별도 root-bind 폴더에 보존한다. full512 pair48MiB는 선택적 진단용이며 런타임용이 아니다.
