# R71 motif regression fixture

`scripts/r71-regression-fixture.py` runs after the R69 owned-delay-queue patch. It makes an exact, fail-closed replacement of only the two `qa-thread-target-*` dummy clones in the generated R65 regression source. The clone points are 0.35 and 0.90 tiles from the original player location; the dummies use ranged behavior, have special boss/action flags cleared, and stay in recovery so their AI cannot move or attack during the motif queue. They explicitly carry `r61PreserveHealth` and `r61PreserveDamage`: R61 stores normalization state in a `WeakMap`, which is not copied by the fixture's object spread, so these flags preserve the intended 10,000,000 HP dummy budget through native R61 room normalization. The original room actors are restored after the fixture.

R70 `nearestFree()` uses free spots at radii 1.0, 1.25, or 1.5, then falls back to the unblocked original player position when the target is within two tiles. Thus each native strike places the player at most 1.5 tiles from its target (fallback is at most 0.90). The two dummies are 0.55 tiles apart, so even the conservative cross-target bound is 2.05 tiles, within the native 2.1 strike and 2.3 sub-hit guards. R70 `hitEnemy()` changes HP and presentation effects but does not move the enemy in world space; the fixture does not alter either range guard.

The patch requires the R69 queue-wait marker, the native `cast(true)`/`hitEnemy`-base markers, and exactly one occurrence of each original 18-sub-hit, one-fractal, six-group, and 1.35-ratio assertion. Drift or duplicate application fails closed. It changes no gameplay script or production data.

The generated R65 browser fixture now waits for the R54 campaign transaction to finish (`busy === false`, `stage === 'playing'`, no error) and verifies the native game is booted, started, unpaused, and has a player and room. Its former `started && !loading` check plus an 800 ms sleep could continue while `begin()` was still awaiting native game setup; the original `dist00` entry assertion remains unchanged. The exact-anchor patch was checked on a temporary generated source, passed `node --check`, and refused a second application.

The health browser check captures the R70 `dist00` midboss maximum before saving and closing that page, then compares the same actor after native R71 entry. It records both rows in `browser.json` and verifies canonical HP matches the R70 maximum while visible HP is the exact integer suffix transform. This covers the region's authored midboss in addition to the separate full authored boss-map scan.

Before the isolated native hit, the health fixture saves the current enemy roster and the selected enemy's setup fields; it restores those after recording the admitted player damage, status, and blood effect. The marked-save check then compares the retained room bosses' actual max HP, HP fraction, canonical/base HP, difficulty factors, visible max and normalization marker across two native restore cycles. It asserts the room is unengaged before saving; native `tickEnemies()` skips boss AI while `room.engaged` is false, so boss HP fraction should remain stable. A `R71_HEALTH_INITIAL` console line records the R70/candidate values before strict initial HP assertions.

The expanded-hospital point-drop browser fixture uses the real seeded kill roll and native `hitEnemy` path. It leaves the player at an unblocked, clear-line offset 2.45–2.55 tiles from the drop, outside R71's 1.35-tile pickup range, and centers the camera before capture. Pickup receives the exact drop ID, avoiding the separate flashlight-occluded fixture drop. The post-kill points check allows only a first-clear reward if that native kill completed the map; R62's active `gainXP` wrapper records XP without granting kill-level points. It also asserts the drop remains unclaimed until the pickup call.

## Native boss-map entry fixture

R4 intentionally handles a restore request for a locked map by emitting `LockedRestoreRecovered`, loading the last unlocked safe room, and returning success. That explains a successful native entry promise followed by `hub`; it is unrelated to boss health or portal placement. The R71 browser test starts from the current native version-6 envelope (`hapil.storyworld.depth-full.20261008`) and imports it through `__STORYWORLD4__.restore()`. R5 converts that envelope to the R4 version-4 validation shape, changing only the input's `unlockedRegions.STORY` history to the full ordered list from the public native `campaignOrder()` API. The fixture preserves real progress and existing room rows, then asserts every authored boss map is unlocked through `__STORYWORLD4__.isUnlocked()` before entry. This exercises R4's trusted-save-history validation and route ledger without marking any story clear.

The boss scan enters each map through the ordinary `enterRegion(id,'n',{restore:true,noStory:true,layer:'STORY'})` path with no forced position. R61 supplies its own center-near safe spawn. The test captures the awaited entry result and map/player/portal/transition/StoryWorld/co-op event state immediately and on the next frame; failures preserve these diagnostics and a screenshot. It also asserts the spawned actor is at least 2.1 tiles from every native portal marker. The browser assertions remain CI-only because the installed local Chromium sandbox cannot launch safely.

## Native command capture and late co-op fixtures

The R71 point-beacon browser check calls production `__STORYWORLD_PHASE1__.captureVisual()` and asserts the renderer remains `three` with no fallback. The command recorder is the real `DrawCommands` class; its implemented canvas subset has `beginPath`, `rect`, and `stroke`, but no `strokeRect`. The initial `strokeRect` exception was therefore a production beacon-painter defect, not a test-context gap. The painter was changed to supported path primitives and covered by its own DrawCommands CPU regression; the browser test does not shim the recorder.

Dist00's authored roster has the boss; its live ordinary melee patrols are generated by R70's story-patrol layer. On first clear, that layer's `getRoom` wrapper calls `grandfather`, removing those generated patrols and marking their waves complete. The co-op test now captures an actual live patrol row and its campaign metadata before `completeRegion`, then asserts native grandfathering removed it. Its marked legacy-import input restores that exact actor row and pre-clear wave state while clearing only the fixture's imported `progress.STORY.dist00` bit; native room generation and co-op save import must reconstruct the melee actor. The existing participant reward/claim ledger remains in the save.

The R24 `geometry().ray` API accepts one direction pair, `[dx,dy]`; it returns the distance to the first occluder, not the flashlight radius. The flashlight fixture previously passed two scalars, then also required the hidden point to be less than one tile beyond that wall distance. The test now uses the native direction-pair signature and separately asserts `distance < radius - 0.5` and `distance > rayLimit + 0.1`, while retaining in-view, hidden-point, and mask-pixel assertions against the existing player position and native hospital walls. The expanded point-drop claim reload uses the guarded native restore helper, which acknowledges only an unread `pre` scene whose map matches the saved map; all final map/loading/modal and claim persistence assertions remain enabled.

## Restore narrative and independent cases

Native R70 `restoreSave` enters the saved map with `noStory:true`, then calls `enterNarrative` and correctly reopens any unread current-map intro. The health fixture now closes its upgrades panel through `#upClose`, records the native restore result/runtime state, and acknowledges only a matching current-map `pre` scene through the actual `#storyNext` UI. Its final map/layer/loading/modal assertions and unengaged boss HP/fraction comparisons remain strict. Unexpected panels or other scene types fail. The fixture neither fabricates read history nor removes narrative data.

All eight independent browser cases run through a common result/cleanup wrapper. A failed case records its full assertion, page errors, runtime state and failure screenshots, closes its contexts, and lets other independent cases run. The final gate asserts exactly eight attempted cases and fails if any case or context cleanup failed. The native runner still executes only after the complete browser gate passes. This collects remaining failures in one CI run without masking or skipping assertions.
