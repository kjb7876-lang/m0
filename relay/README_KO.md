# StoryWorld R62 무료 4인 중계 서버

게임은 GitHub Pages, 이 Node.js + ws 서버는 Render Free에 별도로 배포합니다. **이 폴더는 배포 준비물이며 실제 업로드·공개 배포는 하지 않았습니다.** 사용자 승인을 받은 스토리월드 전용 저장소에만 올리고 `hapil1` 및 비공개 projection33 백업과 섞지 않습니다.

서버는 방·연결·입력·상태 전달만 담당합니다. 방장 브라우저가 전투, 난수, 충돌, HP, 사망, 보상, 맵/서사 진행을 판정합니다. 게스트는 자신의 입력을 보내고 방장 상태를 표시합니다. 기존 합일 중계 서버에 연결한 이력이나 호환성을 확인한 증거는 없으므로 독립 서버로 제공합니다.

## 로컬 실행

Node.js 22 또는 24가 필요합니다. 서버 운영자에게만 필요하며 친구는 웹 브라우저만 사용합니다. 자격증명·결제수단은 코드에 넣지 않습니다.

```sh
cd relay
npm ci --ignore-scripts
npm test
npm start
```

기본 포트는 10000, WebSocket 주소는 `ws://127.0.0.1:10000/ws`, 상태 점검은 `http://127.0.0.1:10000/health`입니다. 로컬 테스트만 `ws://`를 허용합니다. 배포 환경에서는 `wss://`를 사용해야 합니다. 개발용 origin 기본값은 localhost/127.0.0.1 HTTP입니다. 커스텀 개발 origin은 `ALLOWED_ORIGINS`에 정확히 지정합니다.

`package-lock.json`에 공식 `ws` 8.22.0 버전·무결성 해시가 고정되어 있습니다. `node_modules`는 GitHub나 Pages에 올리지 않으며 Render에서 `npm ci`가 설치합니다.

## Render Free 배포 준비

사용자가 Render 계정에 로그인하고 GitHub 저장소 연결을 승인해야 합니다. 비밀번호·토큰을 채팅으로 보내지 않습니다. 결제·카드등록·유료 전환은 이번 작업 범위에 없습니다. 무료 계정에서 제공되는 Web Service를 사용합니다.

1. 스토리월드 전용 저장소를 확인하고 업로드/공개 승인을 먼저 받습니다.
2. Render에서 New → Web Service → 해당 저장소를 연결합니다. 저장소 루트에 이 폴더가 있다면 Root Directory를 `relay`로 지정합니다.
3. Runtime `Node`, Plan `Free`, Build Command `npm ci --ignore-scripts`, Start Command `npm start`, Health Check `/health`, Auto Deploy `Off`를 설정합니다. `render.yaml`은 같은 설정의 검토용 Blueprint입니다.
4. 환경변수 `NODE_ENV=production`, `TRUST_PROXY=1`, `NODE_VERSION=24`, `ALLOWED_ORIGINS=https://kjb7876-lang.github.io`를 설정합니다. 소유 계정이 달라지면 실제 Pages origin으로 바꿉니다. origin에는 저장소 경로를 넣지 않습니다. `PORT`는 Render가 주는 값을 그대로 사용합니다.
5. 승인 후 배포하고 Render가 발급한 `https://<서비스>.onrender.com` 주소에서 `/health`가 `storyworld/R62/1`을 반환하는지 확인합니다.
6. 게임의 협동 접속 설정에 `wss://<서비스>.onrender.com/ws`를 입력합니다. 배포 설정으로 고정할 경우 클라이언트 설정 파일에 주소만 저장하고 비밀값은 넣지 않습니다.
7. Pages 하위 경로에서 게임이 로딩되는지 확인한 후 2명 → 4명으로 실제 테스트합니다. 서로 다른 네트워크의 친구 4명 테스트는 localhost 소켓 테스트와 별개입니다.

## 친구에게 보낼 안내

“승인 후 발급되는 게임 URL로 접속 → 협동 → 닉네임·캐릭터 선택 → 방장이 방 만들기 → 나머지는 6자리 방 코드로 참가 → 모두 준비 → 방장이 시작. 최대 4명입니다. 맵·서사는 방장 진행을 따라가며 각자 싱글 저장은 협동 저장과 분리됩니다. 맵 전환 때 모두 로딩을 마칠 때까지 잠시 기다립니다. 짧은 게스트 연결 끊김은 같은 열린 탭에서 재접속하며, 방장이 탭을 닫거나 새로고침하면 방이 종료됩니다.”

실제 게임 URL·서버 URL은 아직 발급하지 않았습니다. 승인 후 확정된 주소를 넣습니다.

## 무료 서비스와 운영 한계

Render 공식 Free 문서상 무료 Web Service는 HTTP 요청·WebSocket 메시지 등 수신 트래픽이 없는 상태가 15분 이어지면 절전될 수 있습니다. 무료 인스턴스 시간은 워크스페이스 기준 월 750시간 한도이고 서비스 재시작·배포 시 메모리의 방과 연결이 사라집니다. 첫 접속에 기동 대기가 생길 수 있습니다. 실제 연결의 생존 확인 ping만 사용하며 절전 회피용 외부 자동 호출을 추가하지 않습니다.

방장의 PC 성능·업로드 회선·브라우저가 세션 성능을 좌우합니다. 백그라운드 탭은 자동 일시정지 신호를 보내지만 운영체제가 탭을 즉시 중단하면 전달이 지연될 수 있습니다. 방장 종료·새로고침·오프라인은 전체 방 종료입니다. 방장 승계, 계정, DB, 거래, 랭킹, 유료 기능은 구현 대상이 아닙니다.

방 코드가 알려진 사람은 참가를 시도할 수 있습니다. 세션 토큰은 게스트 재접속 인증용이며 메모리에서만 보관합니다. 서버는 토큰·닉네임·스냅샷·개인 저장을 로그로 남기지 않습니다. 브라우저 클라이언트는 필요한 현재 플레이 상태만 직렬화해야 합니다. `/health`는 방 목록이나 플레이어 데이터를 노출하지 않습니다.

GitHub 저장소가 비공개여도 일반 Pages에 게시하는 HTML·JS·이미지·음원은 방문자가 공개 다운로드할 수 있습니다. 백업·원본 ZIP·개인자료·비밀키·불필요한 검증 산출물을 배포 목록에 넣지 않습니다.

## 변경·롤백

클라이언트와 서버의 gameId/build/protocol을 함께 관리합니다. 빌드가 다르면 방 참가를 거부합니다. 롤백은 승인된 직전 클라이언트 커밋과 그와 동일 빌드의 서버 커밋으로 함께 되돌리고 재배포합니다. 진행 중인 방은 종료되고 친구들은 새로 방을 만들어야 합니다. 원본 R61과 비공개 백업은 유지합니다. 서버에는 저장 파일이 없으며 협동 저장 내보내기는 방장 클라이언트가 담당합니다.

## 검증 범위

`npm test`는 실제 로컬 WebSocket 연결로 최대 4명, 5번째 거절, 게임/빌드/프로토콜 분리, 방장 권한, 시퀀스/epoch, 로딩 장벽, 늦은 참가, 재접속/토큰 교체, 방장 이탈, 잘못된 메시지·대형 메시지·빈도 제한, 프로덕션 origin/TLS 검사, 서버 종료를 검증합니다. 이 테스트 자체는 게임 맵 지원·GPU 렌더링·서로 다른 네트워크의 원격 플레이를 증명하지 않습니다. 게임 전체 검증표와 공개 배포 결과는 루트 보고서에서 별도로 확인합니다.
